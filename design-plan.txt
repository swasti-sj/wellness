Appointment Booking Web Application – System Design Report (Student)
==========================================================

Project Overview
----------------
This project is a healthcare appointment booking system that allows:

- Patients to:
  - Book appointments with doctors
  - View upcoming and past appointments
  - Cancel appointments
  - View notes from past visits

- Doctors/Admins to:
  - View all appointments scheduled
  - Mark patients as attended
  - Add visit notes post-appointment

Functional Requirements
-----------------------
Patient Features:
- User registration and login (LDAP)
- Book an appointment by choosing a doctor, date, and time
- View upcoming appointment
- View last visit with doctor's notes
- Cancel future appointments

Doctor/Admin Features:
- View list of appointments for a selected date
- Mark appointment as attended
- Add post-visit notes for attended patients
- View history of attended appointments per patient

Booking Rules and Constraints
-----------------------------
- No two users can book the same doctor for the same date and time
- A user cannot book multiple appointments at the same time, even with different doctors
- Users cannot book appointments in the past
- Users can cancel appointments, but only before the appointment time
- Last visit shown should be the latest appointment marked as "attended"

Database Design
---------------
1. User Schema
---------------
{
  _id: ObjectId,
  name: String,
  email: String,
  password: String,
  role: 'user' | 'doctor' | 'admin'
}

2. Doctor Schema
----------------
{
  _id: ObjectId,
  name: String,
  specialization: String,
  availableSlots: [
    {
      date: String, // e.g., "2025-08-07"
      time: String  // e.g., "11:00"
    }
  ]
}

3. Appointment Schema
---------------------
{
  _id: ObjectId,
  userId: ObjectId,
  doctorId: ObjectId,
  doctorName: String,
  date: String,      // e.g., "2025-08-09"
  time: String,      // e.g., "11:30"
  attended: Boolean, // True if marked attended by doctor
  notes: String,     // Notes added after visit
  canceled: Boolean  // True if appointment was cancelled
}

Preventing Duplicates and Conflicts
-----------------------------------
At booking time:
- Check if a slot is already taken for the doctor:
  await Appointment.findOne({ doctorId, date, time, canceled: false })

- Check if the user already has an appointment at the same time:
  await Appointment.findOne({ userId, date, time, canceled: false })

System Architecture and Flow
----------------------------
Frontend:
- React with React Router for navigation
- Axios for HTTP requests
- Token-based authentication with localStorage

Backend:
- Express.js + Node.js
- MongoDB with Mongoose ODM
- JWT-based authentication
- RESTful APIs for booking, fetching, cancelling, updating

System Flow:
1. User logs in → token stored in frontend
2. User navigates to booking page → selects doctor, date, time
3. On form submit, API checks for conflicts and saves the booking if valid
4. Doctors can view appointments → mark attended → add notes
5. User’s dashboard shows upcoming and last attended visit

Optional Integrations and Enhancements
--------------------------------------
- Google Calendar API integration for:
  - Sending booking confirmations as events
  - Reminders and calendar sync
  - Availability management

Why Custom Booking Logic is Still Needed:
-----------------------------------------
- Google Calendar doesn’t enforce mutual exclusivity rules
- You need DB logic to prevent duplicate bookings
- Backend ensures booking constraints are enforced regardless of calendar sync

Scalability and Maintainability Considerations
----------------------------------------------
- Use indexed fields: doctorId, userId, date, time for fast querying
- Avoid fetching all appointments; use paginated or filtered queries
- Track appointment status (attended, cancelled) explicitly
- Store availability in the doctor schema or manage dynamically



Future Work
